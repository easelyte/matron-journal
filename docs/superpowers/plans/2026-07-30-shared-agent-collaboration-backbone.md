## Architecture (from spec §3 — the five chokepoints)

Every single-tenancy site in spec §2 funnels through one of five primitives:

1. **`isMember(db, userId, convoId)`** — the one authz predicate. `authorize()` rewritten to call it; every hand-inlined `owner_user_id` predicate converts to it.
2. **`appendShared()`** — the sole persisted-write chokepoint. `append()` is already the only `INSERT INTO events`; it becomes membership-aware and fans one copy per member in one transaction.
3. **`broadcastJournal(userId, frame, agentDeviceId)`** — journal delivery, called **once per member** by `appendShared`'s post-commit loop (signature unchanged; `hub.byUser` stays user-keyed; the loop is the fan point).
4. **`sendEphemeral(convoId, frame)`** — ephemeral delivery; unions all members' viewing connections; `statusCache`/`toolStreams.buffersFor` re-keyed by `convoId`.
5. **Agent-op authz = `agent_device_id`** — agent write/stream/status/RPC ops authorize on `conn.deviceId == conversations.agent_device_id`, decoupled from human ownership.

**Canonical copy (spec §3.1):** the same logical event exists as N physical rows; **canonical = the owner's `user_id` space**. Member-facing reads scope `user_id = requester`; canonical/agent-facing reads use the owner's copy; **never** read `WHERE convo_id=?` without a `user_id` predicate.

**Key structuring decision (executor must honor):** the spec §6 pseudocode shows the DB transaction and post-commit delivery together. To keep `journal.js` DB-pure (matching the current architecture — `journal.js` has no `hub` access) and unit-testable, split:
- **`appendShared(db, args)`** in `src/journal.js` = the **transaction only** (actor authz in-txn, member SELECT, per-member inserts, per-member unread, canonical `last_seq`/`snippet`, idempotency). Returns `{ perMember: {userId→seq} }` | `{ perReader, reader, seq }` | `{ duplicate: true }`. Pure DB, fast tests.
- **the isolated per-member delivery loop** stays in `src/ws.js` (the `appendAndFan`/`fanOut` region), consuming `appendShared`'s return to call `broadcastJournal(m, frameWithSeq(seq_m), agentDeviceId)` + `pushPipeline.onAppend(m, …)` per member, each in its own try/catch (round-2 M2 isolation). This preserves the existing "delivery lives where `hub` lives" separation.

## Global constraints

- Error frames follow the existing `fail()` convention: `{kind:'control', op:'error', code, ref: msg.op, detail?}`.
- **Anti-enumeration:** a non-member is rejected **identically** to a foreign/missing convo ("not authorized" → `forbidden`, or a 404 on HTTP media). No new oracle.
- **Comment style:** match `ws.js`/`hub.js`/`journal.js` — explain the constraint/invariant, not narration.
- **Migration is destructive-class:** a **pre-migration prod journal-DB backup is a mandatory deploy gate** (spec §10). The first fan-out write is a declared **point of no return** — binary rollback is unsupported; rollback = restore-from-backup.
- Run the repo's full test suite green before every commit. The journal suite has one historically-flaky test (`POST /media over the size cap → 413`) — rerun once if it's the *only* failure.
- Stage specific files only; never `git add -A`.

### T-1.3: `users.id` AUTOINCREMENT — FK-safe, guarded, one-shot rebuild

**Files:** Modify `src/db.js` (`openDb`). Test: `test/db.test.js`.

**Interfaces:** Defense-in-depth vs rowid reuse (spec §4.5). Independent of the T-1.2 transaction because `PRAGMA foreign_keys` cannot be toggled inside a transaction.

> **Risk note (right-size-effort):** the real member-removal/deletion leak fix is the **hard-delete** of event copies (§2.6, T-5.1). `AUTOINCREMENT` is belt-and-suspenders over an already-closed hole, but requires rebuilding the `users` table, which `devices`/`conversations`/`blobs` FK-reference. The spec mandates it (§4.5, AC7-adjacent), so implement it — but sequence it as its own guarded step behind the mandatory pre-migration backup, and **verify with `PRAGMA foreign_key_check` before committing**. This is the single highest-risk migration step; flag it to the reviewer.

- [ ] **Step 1 — failing tests:** (a) old DB with `users(id INTEGER PRIMARY KEY)` (no AUTOINCREMENT, so no `sqlite_sequence` row for `users`); run `openDb`; assert `sqlite_sequence` now has a `users` entry (AUTOINCREMENT active) AND all pre-existing users/devices/conversations/blobs rows + FK links survive intact AND `PRAGMA foreign_key_check` returns empty. (c) **Failure-path test (round-1 blocker — Codex-CM1 + testability-B1):** inject an FK violation before the rebuild and assert the rebuild **rolls back** (the original `users` table survives, no partial `users_new`) AND `foreign_keys` is restored to ON afterward — proving the check runs pre-commit, not post-commit.
- [ ] **Step 2 — implement (foreign_key_check INSIDE the transaction — round-1 blocker fix):** a guarded helper run **after** T-1.2's block. Guard: detect whether `users` is already AUTOINCREMENT — check the stored DDL (`SELECT sql FROM sqlite_master WHERE type='table' AND name='users'`) for `AUTOINCREMENT`; skip if present (one-shot). Rebuild via the SQLite 12-step procedure with the check **before COMMIT**:
  1. `db.pragma('foreign_keys = OFF')` (allowed only outside a txn; `openDb` already set it ON).
  2. Wrap the whole rebuild **+ the FK check** in one `db.transaction(() => { ... })`: `CREATE TABLE users_new(id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL UNIQUE, password_hash TEXT NOT NULL, created_at INTEGER NOT NULL, tools_tier TEXT NOT NULL DEFAULT 'restricted' CHECK(...))`; `INSERT INTO users_new SELECT id,name,password_hash,created_at,tools_tier FROM users`; `DROP TABLE users`; `ALTER TABLE users_new RENAME TO users`; then **`const violations = db.pragma('foreign_key_check'); if (violations.length) throw new Error('FK check failed during users rebuild: ' + JSON.stringify(violations))`** — the throw rolls the whole transaction back (better-sqlite3 auto-rollback), so a violation NEVER commits the destructive swap (SQLite's documented 12-step order: `foreign_key_check` is step 9, before COMMIT step 10).
  3. Restore `db.pragma('foreign_keys = ON')` in a **`finally`** block wrapping the whole helper — so a thrown/rolled-back rebuild can never leave FK enforcement disabled on the live connection.
  - **Ordering:** this runs after T-1.2 so the rebuilt `users_new` includes the `tools_tier` column. Keep the column list in sync with T-1.1's SCHEMA (add a comment cross-referencing it — the two must not drift). **`PRAGMA foreign_keys` toggling stays outside the transaction (it's a no-op mid-transaction — verified claim); only the CREATE/COPY/DROP/RENAME/foreign_key_check are inside it.**

**Interfaces:** Produces the fail-closed ACK. **`tier_ack` is the server's proof-of-containment** — receiving it clears `awaiting_tier_ack`, marks the `tier_transition` `acked`, and **stops the server's downgrade close-retry (T-6.2)**. > **`tier_ack` preconditions (round-4 blockers — Codex-r4-B1/B2). The ACK must NOT be sent until BOTH hold:**
> 1. **Confirmed child exit (Codex-r4-B1):** `killSession` at HEAD only sets `alive=false` + `child.kill(signal)` and returns **without awaiting exit** — so a child that delays/ignores `SIGTERM` could still be alive when a naive post-kill ack fires, defeating the whole close-until-ack fix. Gate `sendTierAck` on an **observed process exit** (await the child's `'exit'`/`'close'` event) with a **bounded `SIGKILL` fallback** (e.g. escalate to `SIGKILL` after ~5s, then await exit again). Only after the PID is confirmed gone may the ack be enqueued.
> 2. **Durable gate state (Codex-r4-B2):** the tier-kill flags (T-7.1) must be **durably persisted before ack** — but `savePersistedSessions` at HEAD uses an in-place `fs.writeFileSync` that **swallows failures**, and `loadPersistedSessions` turns a truncated file into `{}` (fails OPEN). Persist the flags **atomically (temp file + `fsync` + `rename`)** and **propagate failure**; if the persist fails, **do NOT send `tier_ack`** — the server then stays fail-closed (gate held, drain keeps retrying the close, stuck-convo WARN fires), which is the safe outcome. Withholding the ack on any failure is always safe because the server's `awaiting_tier_ack` gate + close-retry (T-6.2) hold containment until a valid ack proves the old session is gone.
>
> Net: **`tier_ack` = (child confirmed exited) AND (kill/gate flags durably persisted)** — anything less withholds the ack and leaves the server fail-closed.
>
> **3. Durable, replayable ACK (round-5 blocker — Codex-r5). `sendTierAck` alone is not crash-safe:** `enqueue()` at HEAD is a bounded in-memory queue that **drops its oldest frame on overflow**, and a bridge crash after confirmed-exit-and-persist but before the ack reaches the server would leave the server `awaiting_tier_ack=1` **forever** — a **safely-wedged** convo (the full-tier process is already dead, so this is a *liveness/recoverability* gap, NOT a containment breach — but the convo stays unusable). Make the ack **at-least-once**: persist a durable **`pendingTierAck`** marker (in the same atomic-persisted session state, set when preconditions 1+2 are met) and **reconcile it** — on **reconnect/startup**, and whenever a `tier_changed` for an already-killed+persisted session is re-received (the server's periodic drain re-emits `tier_changed` — T-6.2 — which reconnect-replays to the bridge), **re-send `tier_ack`**. The server ack op is idempotent (`UPDATE ... WHERE status!='acked'`), so duplicate acks are harmless; the marker is cleared once the server no longer re-emits `tier_changed` for that convo (or on an explicit ack-confirm). This gives the same at-least-once + idempotent guarantee as the server-side outbox, closing the wedge symmetrically.
